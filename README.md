# SoundWave · 多普勒手势实验室

一个可以直接部署到 **GitHub Pages** 的声音手势 demo。用设备扬声器发出高频单音，通过麦克风观察反射信号的频移，实时显示靠近、远离或未检测到明确运动。

这是依据 [SoundWave（CHI 2012）](https://www.microsoft.com/en-us/research/wp-content/uploads/2012/05/guptasoundwavechi2012.pdf) 原理重新编写的浏览器实验。原始需求没有附 Mathematica 源码，因此本项目不是原 Mathematica 程序的逐行移植，也不是论文完整识别器的复现。

## 先试一下

- **模拟体验**：无需麦克风权限，也不发声；通过页面的手势控制观察合成频谱与识别反馈。模拟数据会经过同一个检测器，页面明确标注其来源。
- **真实检测**：在支持 Web Audio API 的桌面浏览器中打开 HTTPS 页面，点击「开启真实检测」并允许麦克风，保持静止完成约 2 秒的背景校准，再在设备扬声器与麦克风附近做靠近、远离动作。
- 使用电脑内置扬声器和麦克风，先从较低音量开始。不要使用耳机：本实验需要声音经过周围空气反射回麦克风。高频声音对部分人仍然可听；如果听到不适的声音，立即停止。
- 点击停止、切换回模拟模式或离开当前标签页，会释放麦克风并停止发声。返回页面后需重新开始真实检测。

麦克风音频只在当前浏览器内分析；应用不录制、不保存，也不上传音频。

实验台采用单屏布局，按视口高度分配 Mel 与速度子图空间。开始控制、紧凑实时监测、双图、核心读数、频率/增益/灵敏度和重新校准按钮保持同屏；原始麦克风波形已移除。监测条显示发射、输入电平、载频/SNR、校准、帧率、谱峰筛选和 AEC/NS/AGC 状态。设备完整名称、帧数、最近识别、频点对照与说明移入「详情 / 说明」弹层。超过 1.5 秒未收到新帧会提示更新中断。输入有声音不代表已收到载频，载频存在也不代表识别到手势。

实时图默认显示横向滚动的 **Mel 时频图**：新采样从右侧进入，历史向左移动，横轴覆盖最近 10 秒；纵轴按 HTK Mel 刻度排列并标注 kHz。采用 128 个 Mel 三角滤波器，对 FFT 功率做权重归一化后转为 dB，使用黑底白迹的固定强度显示：−140 dB 为黑、−80 dB 为白（非声压级），中间按 dB 线性映射；没有自动归一化、伽马增强或视觉降噪。可用「显示增益」在 ±20 dB 内调整亮度，原始频谱、麦克风增益和检测阈值不变。默认放大载频 ±700 Hz，也可切换到 0–Nyquist 的全频段；切换频段、重新校准或停止时清空历史，缺帧时间保持空白。保留「FFT 频谱」用于观察精细频移。下方「速度历史」与 Mel 共用 200 个、每格 50 ms 的时间槽，显示有符号的等效径向速度曲线（m/s），下沿状态条保留靠近、未检出、远离、双向、无载频和校准。双向变化保留两条速度分支，速度估计与手势类别分开：有效局部侧带峰通过质量检验即可产生速度，不等待手势的 140 ms 分类门限。无有效侧带峰、校准、无载频与丢帧处断线，不把未知速度记为零。两图上下排列，共用时间轴。

速度换算采用 SoundWave 论文的反射模型 `fr = f0 × (c+v)/(c−v)`，反解为 `v = c × Δf / (2f0 + Δf)`，取 `c = 343 m/s`。使用检测器当前有效的侧带峰簇频移（独立 45 ms 时间平滑，丢失后清空，重新捕获不继承上个半周期），不是直接声载频的漂移。此处为近似共址收发、径向运动下的等效值；夹角、多个反射体、噪声和峰值误选均会影响它，不能称为标定手速或三维速度。16 kHz / 48 kHz / FFT 8192 时每个 FFT bin 约对应 0.063 m/s，但载频周围 35 Hz 屏蔽区约对应 0.38 m/s，因此无有效侧带不能证明静止，显示两位小数也不代表测量精度。纵轴按该载频的 ±700 Hz 分析范围固定设置，不随当前速度缩放。

Mel 变换仅用于显示，不改变方向检测算法。公式参考 [TensorFlow Mel 滤波器说明](https://www.tensorflow.org/api_docs/python/tf/signal/linear_to_mel_weight_matrix)。

## 环境噪声筛选

在背景扣除之后，候选侧带还须满足：原始谱中确有局部峰、与相邻频点的瞬时背景相比突出约 6 dB（默认灵敏度），以及现有的峰簇集中度与能量条件。先检查多个局部候选，避免只盯最强的宽带噪声隆起；载频屏蔽区截断的单调噪声尾部不能成为虚假峰。两侧条件一致，不增加手势延迟门限，连续速度逻辑保持独立。Mel 始终显示未经过这层筛选的输入。

合成宽带有色噪声测试中，旧版每侧 21 帧均报速度、17 帧报手势；新版本这两项误报均为 0。移动噪声隆起、噪声叠加独立反射峰和周期对称性也有回归测试。这不是远场实测拒绝率：单音与单麦克风不能按距离隔离声源，窄带外部音或真实远处反射仍可能与手部侧带相似。

## 周期速度对称性修正

原实现把速度绑定到已确认的手势类别，并复用跨半周期保留的侧带平滑值。相同的正负真实速度、远离反射比靠近弱 6 dB 的合成回归（16 kHz、峰值 1.8 m/s、周期 1.12 秒、6 个周期）中，在可观测区间 |v| > 0.6 m/s，旧代码两侧有效覆盖率为 72.7% / 45.5%。独立频谱速度估计后两侧均为 100%，峰值为 +1.746 / −1.744 m/s，平均绝对误差约 0.13 m/s。此为合成信号测试，不是用户实际手速的准确度。

同一局部峰质量条件用于两侧，丢失即置为未知；不为了得到对称曲线而镜像、补齐或人为放大较弱一侧。测试还交换弱侧、切换 19 kHz，并覆盖静态干扰、宽带突发和丢失后重捕获。公式保留 `v = 343Δf / (2f0 + Δf)`：16 kHz 时 ±100 Hz 分别为 +1.0685 / −1.0752 m/s，约 0.6% 差异来自反射模型，不足以解释明显的半周期丢失。

## 本机频点对照（2026-10-26）

页面频率范围扩展为 16–21 kHz，依据本机结果默认 16 kHz。16 kHz 属于高频可听范围，不应称为超声。保持数字发射增益 8%，使用 MacBook Air 内置麦克风、48 kHz / FFT 8192；浏览器报告 AEC、降噪、自动增益关闭。每段排除约 2 秒校准期，表中为采样中位数。

| 频率 | 有效时长 | 载频 dBFS | 背景 dBFS | SNR dB | 载频 IQR dB |
| --- | --- | --- | --- | --- | --- |
| 19 kHz | 10.2 s | −83.7 | −135.1 | 51.4 | 0.2 |
| 18 kHz | 11.7 s | −66.2 | −135.3 | 69.2 | 0.3 |
| 17 kHz | 10.0 s | −64.5 | −134.3 | 69.6 | 0.7 |
| 16 kHz | 13.5 s | −51.1 | −132.4 | 81.3 | 0.8 |
| 19 kHz 回测 | 19.1 s | −82.8 | −133.9 | 50.9 | 0.7 |

16 kHz 比初次 19 kHz 强 32.6 dB，回测 19 kHz 与初测仅相差 0.9 dB，支持这台设备当前声学链路在 19 kHz 响应明显偏弱。测量包含扬声器、麦克风、系统和声学路径，不能单独归因于某一硬件，也不能据此推断手势识别准确率。原历史图有宽带竖纹，未证明全部来自手部频移。

「频点对照」表会继续在页面内保存最近 12 段读数的摘要（每段最多 600 个读数，刷新清空）。重复频点分别记录；未检出的帧也统计，避免只选强信号。

## 部署到 GitHub Pages

这个下载包已经把网站文件放在根目录，不需要构建或安装依赖。

1. 新建 GitHub 仓库，解压本 ZIP，把里面的全部文件上传到 `main` 分支根目录。确保 `index.html` 直接在根目录，不要多套一层文件夹，也不要只上传 ZIP 本身。
2. 打开仓库 **Settings → Pages → Build and deployment**，把 **Source** 设置为 **Deploy from a branch**。
3. 选择 **main** 和 **/ (root)**，点击 **Save**。部署成功后打开 Pages 显示的 HTTPS 地址。

也可选择 **GitHub Actions** 发布：上传时保留 `.github/workflows/pages.yml`，将 Source 改为 GitHub Actions，再在 Actions 中运行 **Deploy SoundWave to GitHub Pages**。此下载包的工作流发布根目录；请勿与另一个目录结构的工作流混用。

所有资源使用相对路径，支持 `https://<用户名>.github.io/<仓库名>/` 形式的项目页面。GitHub 免费账户可使用公开仓库发布；其他仓库类型取决于账户方案。

参考：[GitHub Pages 发布来源说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

## 本地运行

在解压后的目录运行：

```bash
python3 -m http.server 8000
```

打开 `http://localhost:8000`。

不要双击 `index.html` 通过 `file://` 打开；JavaScript 模块需要 HTTP 服务。麦克风访问要求安全上下文：HTTPS 或浏览器认可的本机 `localhost`。普通局域网 HTTP 地址不满足该要求。

## 实现方式

| 环节 | 本项目的处理 |
| --- | --- |
| 发声 | Web Audio `OscillatorNode` 正弦波，默认 20 kHz，可在 18–21 kHz 范围内调整；输出增益受限 |
| 采集 | `getUserMedia()` 对回声消除、降噪和自动增益均使用 `{ exact: false }`；读取 `getSettings()` 核验，若仍报告开启则取消启动，未报告则显示无法确认 |
| 频谱 | `AnalyserNode`，8192 点 FFT，使用音频上下文的实际采样率；48 kHz 时频点间隔约 5.86 Hz |
| 校准 | 静止约 2 秒，建立逐频点的背景功率基线；改变载频或输出增益后重新校准 |
| 运动特征 | 排除载频附近约 ±35 Hz 的区域，比较载频两侧约 ±700 Hz 内超出背景的能量 |
| 方向 | 正频移对应靠近，负频移对应远离；同时出现明显双侧能量时显示方向不明确 |
| 稳定性 | 载频存在性判断、背景扣除、时间平滑、持续时间门限，减少弱信号和瞬时干扰造成的误判 |

算法代码在 `doppler.js`，音频启动、取消与资源释放在 `audio-engine.js`，界面和模拟信号在 `app.js`，页面结构和样式分别在 `index.html` 与 `styles.css`。

反射物体移动时，麦克风除了接收到原始载频，也可能接收到频率略高或略低的反射成分。页面显示的频移是侧带特征，不是把整段声音的最大峰当作手势：最大峰通常仍然是扬声器的直接声。

本实现采用背景功率扣除与双侧能量比较。原论文使用的 FFT 窗口、带宽扫描、自动频率选择及复杂手势时序与这里不同。请将其视作可运行、可修改的原理演示。

## 参数与排查

| 现象 | 可以尝试 |
| --- | --- |
| 无法获得麦克风 | 确认 HTTPS、浏览器站点权限和系统麦克风权限；检查是否被其他应用独占；嵌入页面受限时在新标签页直接打开 |
| 没有检测到载频 | 确认扬声器没有静音、未连接耳机、输入设备正确；适度调整音量；将载频从 20 kHz 降至 19 kHz 或 18 kHz 后重新校准 |
| 一直显示静止 | 校准时保持静止；在设备附近较明显地前后挥手；适度提高灵敏度；确认声音没有被系统音效或降噪过滤 |
| 无动作也触发 | 降低灵敏度；避开风扇、移动物体或其他高频声源；调整设备位置后重新校准 |
| 浏览器支持 API 但效果不好 | 扬声器、麦克风、高频滤波、声学几何和操作系统处理均会影响结果；可先使用模拟模式确认页面交互 |

## 能力边界与验证

- 只判断相对声学运动趋势，不能确定反射物就是手，也不能可靠判断左右、上下或绝对位置。
- 页面频移和信号评分用于观察算法；评分不是经实验标定的概率，频谱 dBFS 不是现实声压级。不从频移推算手与设备的距离。
- 内置扬声器与麦克风的相对位置会影响可检测运动方向。某些设备会在 高频段显著衰减，无法通过网页软件消除这些硬件限制。
- 合成频谱测试能够验证方向逻辑、背景校准、弱信号处理等软件行为，但不能证明真实硬件上的识别精度。已实测本机扬声器到麦克风的载频接收；尚未用动作真值标注验证手部反射与识别精度。

完整源码中的检测器与音频生命周期测试使用 Node.js 内置测试运行器，无需 `npm install`：

```bash
npm test
```
